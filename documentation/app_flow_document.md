# App Flow Document for the Money Changer System

## Onboarding and Sign-In/Sign-Up
When a brand-new user arrives at the application, they first see a landing page that briefly explains the system’s purpose. From here, they can choose to create an account by clicking the Sign Up link. On the Sign Up page, the user enters their email address and selects a secure password. After submitting, they receive a confirmation email and verify their account before being allowed to log in. If social login providers are enabled, the user can alternatively click on a Google or GitHub icon, authorize the application, and be redirected back with their session established. Returning users go to the Sign In page, enter their credentials, and are taken directly into the protected dashboard. In the event of a forgotten password, users click “Forgot Password,” enter their registered email, receive a reset link, and set a new password. Signing out is always available via the user menu in the header, clearing the session and returning the user to the landing page.

## Main Dashboard or Home Page
Immediately after a successful login, the user lands on the Dashboard at `/dashboard`. Along the left side is a persistent navigation panel listing Transactions, Master Data, Reports, and Audit Trail. The top header displays the application name, a notification bell, and the user’s avatar. Below the header, key summary widgets show today’s total transactions in foreign currency, current inventory levels, and quick links to start a new transaction or view the latest report. Clicking any item in the sidebar transitions the user to the corresponding section, with the active item highlighted to maintain context.

## Detailed Feature Flows and Page Transitions
When a cashier initiates a transaction, they click the Transactions link or the “New Transaction” button on the dashboard. They are taken to a form under `/dashboard/transactions/new` where they select a currency code from a dropdown. The system automatically loads the current buy and sell rates from the database. As the cashier enters the foreign currency amount and optional customer details, a real-time calculation displays the equivalent value in IDR. Upon submission, the request is sent to an API route at `/api/transactions`, where server-side logic validates the data, writes the transaction record, updates the inventory denominations, and optionally triggers a PDF generator service. The user is then redirected to a Transaction Details page showing a printable receipt and reference number.

For Master Data management, an administrator selects Master Data in the sidebar and chooses between Currencies, Customers, or Inventory subpages. Each subpage lists existing records in a table powered by shadcn/ui components. To add or edit an entry, the admin clicks an “Add” or “Edit” button and fills in a form with fields for currency code, rate, customer ID, or denomination quantities. Submissions go to dedicated API routes under `/api/master-data`, and the list view refreshes upon success.

The Reports section is accessible only to users with Admin or Auditor roles. After selecting Reports, the user can choose a date range or report type, such as daily summary, profit and loss by exchange difference, or inventory valuation. The front end sends a request to `/api/reports`, aggregates the data using Drizzle ORM queries, and renders both a table and chart elements. Users can export these reports as CSV or PDF.

The Audit Trail page shows a chronological list of user actions stored in the audit_log table. Users with appropriate roles can filter by username, action type, or date. Clicking an entry reveals detailed metadata and timestamps.

Role-based access controls are enforced throughout. Kasirs see only the Transactions link, Admins see all sections, and Auditors see Reports and Audit Trail in read-only mode. Unauthorized navigation attempts redirect to a 403 Forbidden page.

## Settings and Account Management
At any point, the user can click their avatar in the header and select Settings. On the Settings page, they can update personal information such as name and email. A Change Password form allows them to enter their current password and set a new one. They can also toggle between light and dark themes and configure notification preferences, such as receiving daily summary emails. After saving, a confirmation message appears and the user is guided back to the dashboard or the last visited page.

## Error States and Alternate Paths
If a user submits invalid data anywhere in the app, inline validation highlights the specific fields with clear error messages. On the Sign In page, entering the wrong password triggers a notification above the form explaining that credentials are incorrect. If a user tries to navigate to a page without the proper role, the application shows a 403 Forbidden screen with a link back to the Dashboard. Network connectivity issues anywhere in the process display a modal or toast indicating that the operation failed and suggesting the user retry. During long-running API calls, loading spinners appear in place of content to let the user know the system is working. Token expiration automatically clears the session and redirects the user to Sign In with a message that re-authentication is required.

## Conclusion and Overall App Journey
From the moment a cashier or administrator signs up and logs in, they are guided into a protected dashboard that keeps daily operations at their fingertips. Cashiers quickly execute currency exchange transactions with real-time rate calculations and immediate receipt generation. Administrators manage master data for currencies, customers, and inventory, while auditors and admins generate detailed financial reports and review audit trails. Settings and profile management are always one click away, and robust error handling ensures smooth recovery from invalid inputs or connectivity hiccups. Together, these interconnected pages and workflows deliver a complete Money Changer system that is secure, intuitive, and ready for real-world use.
